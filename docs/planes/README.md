# Planes

Planes aprobados, listos para ejecutar. Uno por ronda, nombrado por la rama que lo consume
(`feat-contacts-management.md`).

*   Los escribe **`tanda`**, con el detalle que fija su §2: radio de impacto, reusos explicados y el
    bloque de verificación literal al final.
*   Los ejecuta **`obra`** (`claude --agent obra`, pasándole la ruta) o el usuario.
*   **Un plan no lleva progreso adentro.** Nada de tildar pasos: el único doc de estado es
    [`../trabajo-en-vuelo.md`](../trabajo-en-vuelo.md).
*   Cuando la rama se mergea, el plan se va con ella a [`../registro/`](../registro/).
